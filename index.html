How it works

Ask out loud.
Hear it back.

Three steps. No app to install. No form to fill in. Just talk.

01

Sign in

Patients arrive via a link from the clinic. Name + demo password. No email, no download, no friction.

02

Hold & ask

Hold the big button. Speak naturally. Let go. The app transcribes and replies — text and voice — in under two seconds.

03

Hear a calm answer

Every answer comes from the clinic's own aftercare material. The AI cannot improvise. When it doesn't know, it says so and passes it to a human.

Safety design

The safety net runs
before the AI

Trigger words never reach the model. A plain, auditable word list short-circuits the chat route — no inference, no latency, no chance of a model deciding a bleeding eye can wait.

pain bleeding can't see redness flashing lights dark shadow lost sight severe emergency worsening unbearable

If a patient message matches, the model is bypassed entirely. The patient gets immediate escalation guidance — including when to call the emergency number — and the surgeon gets a timestamped flag. A clinician can read the full trigger list in ten seconds and sign it off. Deterministic lists are a feature here, not a shortcut.

Architecture

Two services.
One round trip.

A React patient portal and an Express API server — both TypeScript, both in a pnpm monorepo. Provider credentials never touch the browser or this repository.

Patient portal · React + Vite

  • Hold-to-talk recorder (cross-browser MediaRecorder)
  • Live waveform via WebAudio analyser
  • Tappable chip questions (instant pre-generated audio)
  • Journey timeline + aftercare leaflet views
  • iOS silent-deny detection by response timing

API server · Express 5 + TypeScript

  • RAG over curated aftercare chunks
  • Claude Sonnet — grounded, cannot improvise
  • ElevenLabs flash TTS + in-memory answer cache
  • Deterministic flag triggers (pre-model)
  • Structured pino logging on every request

AI layer

  • Anthropic Claude Sonnet via server-side proxy
  • System prompt enforces knowledge-only answers
  • No-match path → prescribed human handover text
  • TTS respelling: "fayco emulsification" for voice only

Voice

  • ElevenLabs flash TTS for live answers
  • Pre-generated MP3s for greeting + common chips
  • Graceful fallback if key lacks voice-list scope
  • Answer cache keyed on voice · model · text hash
